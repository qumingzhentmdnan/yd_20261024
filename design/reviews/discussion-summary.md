# SafeAgent 双轮设计讨论记录

日期：2026-10-24。用户要求调用 codexx，使用 gpt-6.1-sol、medium；两轮启动日志均确认上述模型和推理档位。评审使用 read-only sandbox，未修改现有设计正文或实现生产代码。

第一轮独立评审见 [codexx-round-1.md](codexx-round-1.md)。第二轮通过新建临时会话读取第一轮原文和主 Agent 的六项质询进行讨论，见 [codexx-round-2.md](codexx-round-2.md)。这不是同一持久会话的 resume，也不是运行测试或对安全性质的验证。

## 总体判断

分层合理，可以进行模块内部开发；不能把当前设计原则当作完整冻结的线协议。后续优先收敛行为与契约权威入口，纯命名修改不应全部视为阻塞。

## 两轮讨论形成的建议

| 主题 | 建议 | 代价或约束 |
|---|---|---|
| 契约入口 | 选定唯一接口文档，增加采纳/拒绝/后置表；统一 HTTP /start 只到准备完成，/sessions 启动 Agent | 历史调研建议不能与执行契约具有同等权威 |
| VM 生命周期 | VMRef 表示资源，VMInstance 包含启动 epoch；采用独立 Wait，明确 Stop 完成条件和 context 取消行为 | 通道断开与 VMM 退出必须分别处理 |
| 开工与验收 | 两小时 spike 验证设备、Hello、echo、基本关闭；候选 schema 确定后允许内存 framing、fake 和双端实现并行 | 协议稳定交付前仍须通过畸形帧、取消、去重等共同验收；spike 通过不等于协议成熟 |
| 单次运行 | MVP 一个 boot epoch 仅一个顶层 Session；唯一启动记录保留到本次运行结束，同操作重试返回已有结果，其他启动拒绝 | 自然退出不释放启动名额，新任务创建新 VM；减少去重缓存和恢复复杂度 |
| daemon 失效 | guestd 重启使运行失效，撤权并停止 VM，不自动恢复 | 必须能识别 daemon 换代；VM epoch 单独不足以发现 Guest 内 daemon 重启 |
| 终端 | 无 attachment 持续读取并丢弃输出；有 attachment 使用有界队列，满则断 attachment | 显式提示 output gap，不提供历史补读；Close 不杀 Agent；退出与 EOF 分离，有界排空尾部输出 |
| 正常停止 | 撤权 → 终止 Agent 与所有受管理写入者 → 活 Guest 提取并验证 Host 快照 → 停 VM | 整体有总时限，提取失败继续停 VM；不能只等待顶层进程退出 |
| 异常停止 | 先隔离并停止，不等待文件提取；只将完整校验后的 Host 快照标记为可导出 | 保留 overlay 不等于承诺恢复；没有快照必须明确不可导出 |
| 多流验证 | 最早的流式模型请求接通后，立即同时运行 SSE、终端输出与控制 RPC，并人为慢读一路 | 验证其他流仍推进、取消和停止有界；echo 仅证明连通，不能证明无饥饿 |

这些是讨论建议，尚未自动成为设计正文中的正式约束；涉及范围收缩的单 Session 限制、输出丢失和异常不可导出，需要在正式修订时明确写入产品行为与验收。

## 第二轮的实质修正

- 主 Agent 反对将所有命名提案视为 P1；评审方接受，真正阻塞是契约入口和完成语义不唯一。
- 主 Agent 反对让全部真实负向验收阻塞候选实现开工；评审方接受拆分门槛，候选实现可以并行，稳定交付仍须验收。
- 评审方补充：进程停止必须覆盖工作区写入者，guestd 换代必须可检测，输出丢失必须用户可见。主 Agent 同意这些条件。

## 下一步最小交付物

1. 唯一契约入口及接口采纳表，落实 VMInstance、Wait 与 /start 语义。
2. 单 Session 状态与授权撤销表，覆盖去重、自然退出、daemon 重启。
3. 主平台候选拓扑、可执行启动配置及 Hello/echo/关闭实测记录。
4. 共用协议和生命周期验收套件，覆盖 PTY 溢出、取消与 SSE 并发控制。
5. 有总时限的停止/快照流程及明确的导出可用状态。
